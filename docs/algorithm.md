# 自動売買アルゴリズム v1

目的は、上昇トレンドがある銘柄に参加し、トレンド崩れで退出する日足の現物運用。日米共通のルールで動き、相場を見ながら人が注文ボタンを押す必要はない。銘柄ごとの収益性を確認した戦略ではなく、まず実データで評価するための基準戦略である。

## 1. 買い条件

各銘柄の過去60取引日以上の終値が揃い、次の3条件をすべて満たすこと。

1. 終値が60日単純移動平均を上回る。
2. 20日単純移動平均が60日単純移動平均を上回る。
3. 20日前からの騰落率がプラス。

未保有銘柄を20日騰落率の高い順に検討する。価格データの欠けている日は新規判断を行わない。市場全体の指数・決算・ニュース・出来高は現在の入力データにないため判断に用いていない。

## 2. 数量

| パラメータ | 中リスク | 高リスク |
| --- | --- | --- |
| 1回の想定損失枠 | 総資産の1% | 総資産の2% |
| 損切り幅 | 10% | 15% |
| 1銘柄の購入時保有上限 | 20% | 30% |
| 総株式比率の購入時上限 | 80% | 90% |
| 口座最高値からの買付停止幅 | 25% | 40% |

投資予算は「想定損失枠 ÷ 損切り幅」と銘柄比率上限の小さい方。現金余力も考慮し、3%の価格変動余裕を差し引き、日本株100株・米国株1株単位で切り下げる。1単位を買えなければ見送る。初期資金100万円の高リスクなら、1回の予算目安は2万円÷15%=約13.3万円、余裕分を引いて約12.9万円。

これは通常の損切りでの想定損失であり、最大損失ではない。ギャップ・為替変動・執行遅延では上回り得る。実際の約定日に価格・費用・余力・比率を再チェックし、違反時は拒否する。ナンピン、空売り、信用取引、レバレッジは行わない。

## 3. 売り条件

- 保有銘柄が買い条件を満たさなくなった。
- 円換算・取得費用込みの保有評価が損切り幅を超えて下落した。
- 口座全体が最高評価額から規定の下落幅に達した。この場合は新規買付を止めて保有を売却し、口座をリセットするまで買付停止を維持。

固定の利確率は設けず、買い条件が続く限り保有する。最高値から一定幅で追随するトレーリングストップは未実装。

## 4. 判断から執行まで

1. 現在日までの価格だけで判断。
2. 注文を予約。
3. 次のデータ日へ移り、その銘柄が取引している日の始値で約定。
4. コスト・為替・ポジション・損益を更新。
5. 終値で損切りと口座下落上限を評価し、必要な売却を次の取引日に予約。
6. 保存して繰り返す。

実装は `automaticStep` → `strategyOrders` → `advance`。バックテストと同じ戦略・約定処理を用いる。自動再生とバックテストの口座・取引履歴が一致すること、未来のデータ変更が過去の注文に影響しないことをテストする。

## 5. 操作・停止

- 「自動売買を開始」: 画面が表示されている間、約0.7秒でデータ上の1取引日を再生。
- 「20日分を自動実行」: 最大20データ日分で自動停止。
- 「停止」: 再生を停止。ポジションや待機注文を消去・強制決済しない。
- 再読み込み、画面非表示、設定・戦略・未来画面への移動で停止。自動再開しない。
- データ末尾、保存エラー、処理エラーで停止。口座下落上限では新規買付を止め、保有売却と待機注文処理を終えてから停止。
- Web Locksで同じブラウザの複数タブによる同時自動実行を防ぐ。他タブで保存内容が変わった場合は停止し、保存データを読み直す。

## 6. 目標と限界

10年で100倍には、積立なしで年率58.49%の複利成長が必要。この戦略がその目標を達成できる根拠はまだない。パラメータを目標額に合わせて調整し、過去データにだけ合う結果を作らない。

次の評価は、実際の日米株価と為替、売買コスト、上場廃止銘柄を含む適切な銘柄群で行う。開発に用いない期間を確保し、上昇・横ばい・下落局面、買い持ちとの比較、最大下落・売買回数・コスト感応度を確認する。横ばい相場では売買の往復が増え、急落時には損切りが間に合わないことがある。

現段階では合成データまたはCSVの過去データ再生のみ。市場データを日々取得する無人ペーパー運用、常時稼働サーバー、楽天証券への実発注、通知・監視は未接続。実運用への拡張時にはそれぞれを追加する。楽天証券RSSの公式注文仕様についてはREADMEを参照。
