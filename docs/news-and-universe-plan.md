# ニュース取得と日米銘柄拡張の研究計画

2026-10-24。公式資料を確認して作成した設計・調達候補であり、ニュース連携や500普通株での検証が完成したという意味ではない。既存の9系統22,500試行は5ETFのみ。以下の仮説は未検証で、既存結果の成績には含めない。

## 判断

価格・上場履歴の品質を先に整え、日米各250銘柄を基本に各200・300でも比較する。ニュースは企業の一次開示から始め、「ニュースなし」に対する追加効果を測る。ニュースを多く集めるだけでは優位性にならず、取得遅延・重複・費用を含めて評価する。

現在の有名企業を500社並べても後知恵は解消しない。保管する母集団は各時点の市場全体で、そこから当時の情報で監視対象を選ぶ。10年間で登場する企業の延べ数は500社を超える。ニュースが多い企業だけを選ばず、ニュースのない銘柄も価格戦略の対象に残す。

## 取得元の候補と不足

| --- | --- | --- | --- |
| 日本の価格・銘柄マスター・財務 | [J-Quants V2](https://jpx-jquants.com/ja/spec/data-spec) | プランと項目で履歴期間が異なる。10年検証には指標計算用の開始前データも必要 | 利用可能な契約範囲と実データを確認してアダプターを作る |
| 日本の当時の投資対象 | [J-Quants銘柄マスター](https://jpx-jquants.com/ja/spec/eq-master) | 過去日付の対象を取得可能。ただし過去単元、企業行動履歴、実際にデータが利用可能になった時刻、訂正前データは提供されない | 不足を別資料で照合。未確認のままPIT完全性フラグを立てない |

| 日本の法定開示 | [EDINET](https://disclosure2.edinet-fsa.go.jp/WEEK0010.aspx) | API Version 2の公式案内がある。適時開示とは対象・提出タイミングが異なる | 仕様・登録条件・保持期間を確認し、有報・大量保有等の別系列として取得。TDnetの代用品とは扱わない |
| 米国の企業開示・財務 | [SEC EDGAR API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) | 提出履歴・XBRL、APIキー不要。現在の企業メタデータは歴史的な銘柄マスターではない | 提出文書単位の時刻と訂正を保持。株価・単元・上場廃止データは別途必要 |

| 米国データの実行環境 | [Norgate Updater FAQ](https://norgatedata.com/ndu-faq.php) | UpdaterはWindows用。現在のLinuxサーバーにそのまま接続できる前提にしない | 許諾されたWindows取得・転送構成か、必要項目を満たす別配信元を比較 |
| 一般報道・ニュース感情 | [Alpha Vantage NEWS_SENTIMENT](https://www.alphavantage.co/documentation/#news-sentiment)等 | API候補。日米の対象範囲、10年分の完全性、当時の配信時刻・スコア算出モデルは未検証 | 優先度を下げ、少量サンプルで欠落・重複・時刻を監査してから採否判断 |

企業IRの公式RSS・配信APIも補完候補。更新時刻や保存版がないページを、過去検証の証拠にしない。一般検索は取得元の調査に用い、過去の全ニュースを網羅したデータとして扱わない。

J-Quantsの日付指定は休業日に翌営業日のマスターを返し、提供開始より前の指定でも開始時点の値を返す場合がある。要求日ではなく返却された情報適用日を検証する。過去履歴の取得だけで「当時利用できた版」を完全に証明できるわけではない。

有料契約・APIキーは未取得で、新規課金はしていない。生データ・ニュース本文・キーを公開GitHubや静的サイトに置かない。個人利用、保存、クラウド処理、LLM送信、画面表示の利用範囲は配信元ごとに確認する。

## 取得・保存の設計

サーバー側の定期取得 → 原文保存 → 正規化 → 時点付き特徴量 → 研究・ペーパー運用という経路にする。スマホは最終更新時刻、欠落、対象数、判断根拠、原典リンクを表示する。現在のSitesは静的画面であり、この取得サーバー・常駐ジョブは未実装。

1. APIのページングを最後まで進め、カーソルと成功範囲を保存。差分取得は直前区間を重ねて取得し、後着・訂正を検出する。
2. 配信元の制限に合わせて速度制御し、429/5xxには上限付き再試行。SECは全ワーカーを通じて制御する。[公式制限](https://www.sec.gov/about/developer-resources)を超えない余裕を持つ設定と識別用User-Agentを使用する。
3. 文書ID・版・本文ハッシュで再取得を冪等にし、同じ発表の転載をイベント単位に束ねる。訂正原文は上書きせず追加する。
4. 発行体IDと証券IDを分ける。CIK/EDINETコードはそのまま証券の恒久IDにはしない。銘柄コード・社名・複数株式クラスの対応表を有効期間付きで保持する。
5. ページ欠落、古い応答、ID未解決、異常値は隔離する。「情報なし」と「取得失敗」を分け、失敗時に好材料・中立とみなさない。ニュース依存の新規判断を保留し、既存ポジションのリスク管理は継続する。

最低限のニュースレコード：`source`、`document_id`、`version`、`issuer_id`、`security_ids`、`published_at`、`provider_available_at`、`first_seen_at`、`feature_ready_at`、`source_url`、`content_hash`、`event_type`、`supersedes`、`availability_basis`、`extraction_version`。時刻はUTCオフセット必須、不明値を勝手に午前0時で埋めない。

前向き観察で使用できる時刻は、公表・配信・初回受信・特徴量完成のうち最も遅い確認済み時刻。今日収集した過去記事を、過去に自分のシステムが受信したことにはしない。履歴再生では当時の配信記録か、明示した遅延仮定を別フィールドに保存し、「実測」と「仮定」を別集計にする。発表日時も不確かな記事は時刻依存の売買検証から除く。

財務値は会計期間末ではなく公表後から使用し、後日の修正値で過去を上書きしない。予想との差を使うなら、その時点の市場予想履歴も必要。なければ会社の従前予想との比較か前年同期比と呼び、市場予想サプライズと混同しない。

LLMは最初は事象・数値・根拠箇所の抽出に限定し、結果をキャッシュする。モデル版・プロンプト・抽出結果を固定し、試行ごとに記事を読み直さない。現在のLLMが後年の企業業績を知っている可能性は、記事の時刻を正しくしても残る。過去記事のLLM感情評価は探索用とし、厳密な優位性判断にはルールベース抽出との比較と新しい記事での前向き観察を必要とする。匿名化だけで解決したとは扱わない。

## 対象銘柄の増やし方

取得母集団 → 適格集合 → 月次監視集合 → 保有集合を別々に保存する。市場範囲は最初は日本＝東証普通株、米国＝選定した主要取引所の普通株と明記し、日米全市場を網羅したと表示しない。

- 各時点で上場していた銘柄を含むマスターを保存し、上場廃止・吸収合併・コード変更を追跡する。現在のS&P500や日経平均構成を過去へコピーしない。
- 前月末までに利用できた252営業日以上の価格、過去60営業日の売買代金、当時の業種・規模を使用する。新規上場の履歴を作らず、必要履歴を満たした後に候補へ入れる。
- 基本250は大型125・中型125、200は100ずつ、300は150ずつの比較案。同じ母集団・流動性条件・業種制約・選択順を固定し、候補数の効果を分離する。サイズ区分の境界も当時の情報で定義する。小型・IPO枠は別実験とし、数合わせで混ぜない。
- 250を揃えられない月は実数と理由を表示する。すでに保有する銘柄は監視対象から外れても追跡を継続し、予定された退出ルールで処理する。
- 「株価が上がったから対象へ追加」ではなく、固定された流動性・履歴・層別選択ルールを毎月再実行する。月次入替による売買費用も評価する。
- 楽天での取扱、注文方法、単元、100万円での買付可能性は研究対象への適格性と別に判定する。現在の楽天取扱一覧を10年前の売買可能性として使わない。

既存`v2_engine.py`はこの月次選定の一部を実装済みだが、過去マスター等の実データは未取得。9系統の高速ETF探索を500普通株へ直接流用せず、投資可能集合のマスク、時刻順イベント、上場廃止、配当、整数株、通貨別現金を扱うアダプターを作り、上位候補は詳細エンジンで再生して照合する。

## 新たに比較するアルゴリズム

以下はパラメーター違いではなく、使用情報と売買仮説が異なる未実装の研究候補。原則ロングと現金で始め、売買条件・保有期間・退出・リスク制約をデータ取得後、成績を見る前に固定する。

| 系統 | 仮説と比較 | 必要な追加情報 |
| --- | --- | --- |
| 成長性・収益性・価格の複合順位 | 業種内で財務健全性と成長性を比較し、価格のみの順位に勝るか | 公表時点付き財務、業種・規模 |
| 決算後の継続上昇 | 利益改善を公表した後の中期的な反応を検証 | 当時の決算、比較可能な前年値。市場予想は別途取得した場合のみ |
| 会社業績予想の修正 | 上方修正への参入と下方修正時の退出 | 従前予想と新予想の版・公表時刻 |
| 自社株買い・資本政策 | 発表規模と財務余力で選別し、実施・中止で更新 | 発表額、当時の時価総額、実施報告。発表を即実行とみなさない |
| 悪材料による損失回避 | 同じ価格戦略に、減配・不正会計等による買付停止・退出を追加 | 事象分類、訂正、売買停止・翌約定可能価格 |
| ニュース後の過剰反応・反転 | 確認された事象後の急変から戻る仮説を、決算後順張りと比較 | 事象時刻、価格・出来高。悪材料を一律買いにしない |
| 業種への情報波及 | 企業・業種ニュースが同業他社へ遅れて反映されるか | 当時の業種関係、重複除去済みイベント。未来の供給網を使わない |

市場全体の金利・政策・為替ニュースは、企業ニュースと混ぜず国・業種の投資比率調整として後続研究にする。改定済みの経済指標を当時の初回発表値に代用しない。

## 比較と採否

1. 日米各200・250・300で価格のみの基準運用を比較。日米別・合算、円換算・配当・売買費用・FX費用を揃える。S&P500と日経/TOPIXに加え、同じ候補集合の単純配分とも比較する。
2. 同一期間・同一対象で「価格のみ」「価格＋財務」「価格＋企業開示」「価格＋一般報道」を比較。ニュース有無の効果を対象変更の効果と混同しない。
3. 利用可能なニュース期間に合わせて両方のモデルを再実行する。5年しかないニュースをゼロ埋めして10年版にせず、該当期間は評価不能と表示する。
4. 時系列で学習・選別・次区間を分離。最大保有期間に応じて境界を隔て、前処理も学習区間だけで決める。仮説・候補数・目的関数を事前固定し、不採用・失敗も台帳に残す。
5. 重複する10/5/1年窓を3つの独立証拠と数えない。既に見た期間は開発・診断用。複数開始月・相場局面、国別・業種別、利益上位銘柄除外、費用2倍、ニュース遅延、配信障害で確認する。
6. 多数探索による偶然の勝者に対応するため、全試行数を含む多重比較補正と時系列ブロック再標本化を設計し、最良利回りだけで採用しない。選別済み候補を固定し、新しいデータで検証する。未見データがなければ期待超過収益は未確認とする。
7. 年率収益・超過収益に加え、最大下落、回復期間、回転率、現金比率、利益集中、単元による注文拒否、ニュース欠落率、抽出精度・遅延、運用費を報告する。

データ料も判断材料にする。TDnetアドオン月11,000円なら年132,000円で、元本100万円の13.2%に相当する単純計算（基礎プラン・他の費用は別）。これはCAGRへの一律13.2ポイント控除ではなく、資金推移に応じた実額費用として別台帳で評価する。研究開発費と継続運用費を分け、運用費控除前後を併記する。現状は低コストで取得可能な開示と価格を優先し、有料ニュースが十分な追加利益を生むと仮定しない。

## 実装順と完了条件

1. **取得契約・サンプル監査**：各配信元の利用条件と履歴範囲、上場廃止・分割・合併・過去単元・財務訂正・日付境界を含むサンプルを確認。不足と代替を一覧化する。未完了。
2. **取得・時点管理**：アダプター、差分・再試行・重複防止、ID対応、追記保存、品質レポートを実装。未来の文書・訂正・価格を変更しても過去判断が変わらないテストを通す。未実装。
3. **銘柄拡張**：各200/250/300の月次候補と不足理由を出力。500銘柄以上のデータで性能計測し、高速探索と詳細再生を照合。未完了。
4. **情報追加の実験**：取得できた情報に対応する仮説だけ実装し、探索設定と全結果を保存。Sol/Sonnetへは固定済みコード・データ・シード・分担範囲を渡す。LLM呼出しは抽出時に集約し、数万試行は数値計算で行う。未実施。
5. **スマホ・前向き観察**：候補数、最新取得、事象と原典、採否理由、監視停止を表示。採用判断は別途行い、楽天の注文接続へ自動で進めない。未実装。

今回完了したのは取得元の調査と、この実装・評価計画の保存。ニュース取得済み、500銘柄化済み、将来のS&P500超過を確認済み、とは表示しない。
