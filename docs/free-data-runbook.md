# 無料データで進める実行手順

2026-10-24。ユーザー指定により、データ購読料・追加の有料サービス・外部AI APIの予算を0円とする。有料データ、課金に移行する試用契約、有料サーバーは前提にしない。研究は既存PCで実行可能なCLIを基本にする。通信・電力や既存サービスの契約料まで0円と保証する意味ではない。

## 今回実装した範囲

`scripts/fetch-free-data.py`は登録・キー不要の次の公開データを取得し、ローカルに保存する。HTTP取得を今回実行して確認した。

| 取得元 | 保存するもの | 限界 |
| --- | --- | --- |
| [JPX上場銘柄一覧](https://www.jpx.co.jp/markets/statistics-equities/misc/01.html) | 掲載中の月末銘柄一覧、業種・規模区分 | 日次の投資可能集合ではない。月末時点と翌月の公開日・自分の取得日を区別する |
| [Nasdaq Symbol Directory](https://www.nasdaqtrader.com/trader.aspx?id=symboldirdefs) | Nasdaq上場・その他取引所上場の2ファイル、作成日時ラベル | ETF・優先株等も含む。普通株候補は名称等による仮分類で、確定済みの商品マスターではない |
| [SEC最新開示フィード](https://www.sec.gov/about/developer-resources) | 文書ID、種別、更新時刻、原典URL、提出者等の表示情報 | 最新100掲載行だけ。同じ文書の複数掲載をまとめるため保存文書数は100未満になり得る。全文・全履歴ではない |

日本普通株候補や米国普通株候補の数は、銘柄選定・価格取得・楽天の取扱確認を終えた数ではない。米国の名称判定には漏れや誤分類があり、取引所のround lotも楽天の最低注文数量とは別なので、売買単位へ転用しない。証券の恒久ID、過去単元等は未確認として空値を維持する。

## 実行

```sh
python -m pip install -r research/free-data-requirements.txt
python scripts/fetch-free-data.py
# 1取得元だけ再実行する場合
python scripts/fetch-free-data.py --source sec_filings
python -m unittest discover -s tests -p 'test_free_data.py' -v
```

保存先は`research/history-free-data/`。別の保存先は`--output`で指定する。既定ディレクトリはgit管理外で、生データをGitHubやサイトに公開しない。

- `raw/`：取得応答をSHA-256名で保存。
- `observations.sqlite3`：情報の版、初回取得時刻、取得バッチと各版の対応、失敗を保存。同一内容の再取得で初回取得時刻を書き換えず、訂正や元の内容への復帰も各バッチから追える。
- `status.json`：最後の実行の成否、件数、日付、ハッシュ、未整備項目。`--source`使用時はその実行で指定した取得元だけを表示する。

1つの保存先では1プロセスだけを動かす。取得は直列で、429/5xx等は最大3試行。HTMLエラーページ・未完の一覧・不明な時刻・未来日付を成功として取り込まない。1取得元の失敗を記録して他の取得元は継続し、いずれか失敗した実行は終了コード1になる。HTTP成功だけではデータの鮮度・完全性は保証されないので、返却日付・件数も確認する。

初回取得時刻は受信時刻であり、記事の公表時刻ではない。SECの`updated`は`provider_updated_at`として保持し、公表時刻を推測で埋めない。今回集めた過去日付の情報を、過去の自分のシステムが使えたことにはしない。銘柄一覧から消えた企業についても、旧版を保存するだけで上場廃止理由・清算金額が確定するわけではない。

このCLIは市場データの自動取得処理だが、常駐収集・定期ジョブ・スマホ同期は設定していない。PCの既存スケジューラで実行する場合も、有料クラウドを追加せず単一起動にする。SECの最新フィードは取得間隔が長いと取りこぼすので、完全な開示記録を必要とする戦略には日次インデックス等との照合・欠落補完を先に実装する。

## 無料制約に合わせた研究の進め方

1. 今回のマスター候補から、普通株の種別確認、価格・流動性・企業行動の無料取得方法の確認へ進む。価格や履歴がない状態で先頭250銘柄を選び、日米500銘柄対応と表示しない。
2. 当時の上場・上場廃止・企業行動まで揃わない10年検証は「現存銘柄に偏る参考値」等と明記する。PIT完全性を偽って既存エンジンの検査を通さない。揃った項目・期間だけで検証する。
3. 日本の開示はEDINET APIや各社の公式配信を次の調査対象にする。EDINETはTDnet全体の代替ではない。日本企業ニュースの取得・銘柄対応付けは今回未実装。
4. J-Quantsの無料枠は必要に応じて別途検討するが、登録・キー未設定。[プラン仕様](https://jpx-jquants.com/ja/spec/data-spec)上、Freeの価格・銘柄等は直近12週間を除く2年間で、10年の履歴や最新運用の代用にはできない。
5. ニュース分類はルールと数値抽出から始め、外部LLM APIを呼ばない。開示が増えたか、取得が失敗したかを分離し、価格戦略に加える効果を同じ期間・対象で比較する。
6. 日米各250（200/300も比較）の確定候補を作るのは、価格・流動性・必要履歴・商品種別を照合した後。前向きに蓄積した記録も使い、無料で取れない過去を推測で作らない。

最新の既存22,500試行は引き続き5ETFの結果であり、今回の一覧取得で500普通株の結果に変わるわけではない。実発注も行わない。
