# 次期設計：日米各250銘柄を継続評価する仕組み

2026-10-24。ユーザーの指摘を受けた設計の改訂。これは実装済み機能・検証済みの収益戦略ではない。現行アプリは6銘柄の操作用試作であり、日米各250銘柄のデータ取得・運用にはまだ対応していない。

## 前回検証の位置付けを訂正する

現在の有名な6銘柄を選び、その過去成績を使った試算では、将来の有望銘柄を見つける能力は評価できない。特に5年利益の約61%がNVIDIAに依存することは、この偏りを示す。過去の銘柄選定ルールを再現していないため、同銘柄を当時選べたとは主張できない。

前回の金額は指定6銘柄・指定ルールの条件付き概算として残す。将来10年の銘柄選択能力や戦略の優位性を示す証拠として扱わない。現在の指数構成銘柄500社等をそのまま過去へ遡っても、この問題は解決しない。

## 1. 監視対象を選ぶ規則

設計目標は日本250銘柄・米国250銘柄、合計500銘柄。250が最適だと実証したわけではなく、ユーザー指定の各200〜300銘柄を満たす初期設計値とする。

- 母集団は、当該時点で上場していた各市場の普通株。現存企業だけに絞らず、上場廃止・合併・銘柄コード変更を識別できる恒久IDを持つ。
- 選定に使える情報は当該時点までに公表されたものだけ。価格、売買代金、上場状態、株式数、業種、決算の公表時刻を履歴で管理。
- 流動性と履歴の条件で適格銘柄を絞り、業種および時価総額帯が偏りすぎないよう250候補を抽出する。流動性は過去60営業日の売買代金中央値等を候補とし、適格閾値と層別配分は開発期間で固定する。
- 毎月末の確定情報から翌月の候補を決める。月末の結果で同日の始値へ遡って発注しない。候補集合・選定理由・落選理由を保存する。
- 大型株だけに固定せず、流動性を満たす中型株にも候補枠を設ける。成長株の将来発掘を試す場合は、現在の時価総額順位で過去の候補を決めない。
- 新規上場銘柄は事前定義した履歴条件を満たしてから参加。売買停止・上場廃止は当時利用可能な情報と実際の処理条件で扱い、履歴から消さない。
- 適格銘柄が不足する場合は不足理由を表示し、条件を黙って緩めない。250候補から外れた保有銘柄の処理も事前定義する。

必要なのは『NVIDIAを選ぶ規則』ではなく、NVIDIAが将来上がると知らなくても適用できる選定規則である。次の勝ち銘柄が候補集合に入る機会を作り、同時に失敗企業も評価対象に残す。

## 2. 候補の評価と売買判断

500銘柄を監視することと、500銘柄を保有することは別。銘柄選択・エントリー・保有継続・退出を独立した役割として設計する。

候補として比較する情報は、6〜12ヶ月の相対的な価格の強さ、変動率、流動性、当時公表済みの成長性・収益性・財務健全性など。まだ最適な期間・配点・閾値を決めたことにはしない。決算データが公表時点付きで取得できない場合は、財務情報なしのモデルとして別に評価し、後日修正値を過去に使わない。

現行MA20/60を基準モデルとして残し、各改善候補を別々に比較する。参入に必要な条件をそのまま全売却条件にせず、順位の小さな変動で往復売買を起こさない緩衝帯、週次判断、トレンド継続中の保有などを検証する。新しい指標を足しただけで改善と認定しない。

## 3. 100万円で実行できるポートフォリオ

現行の高リスク予算は1回あたり初期資金の約12.93%。日本株100株単位と整合しないため、候補の買い付け可能性を評価段階から確認する。

- 商品マスターに実際の売買単位・通貨・取扱条件を保持する。銘柄数を増やしても全商品を一律100株にしない。
- 売買単位を満たす整数数量で、総リスク、1銘柄、業種、国、通貨、相関の上限を評価する。個々の損切り幅だけでは、複数銘柄の同時下落を管理できない。
- 購入できない理由（単元・予算・既存リスク・相関等）と、機会損失、現金比率を記録する。監視500銘柄でも実際3銘柄しか買えないなら設計を見直す。
- 保有数は資金・単元・リスク制約から決める。100万円で20銘柄などの数だけを先に固定しない。
- 株式比率は市場環境とリスク予算から決める。平均13〜19%に落ち着いている原因を解消するが、常時90%へ機械的に引き上げない。
- 単元未満取引を使う場合は、予定する証券会社の正式な対応商品・発注手段・約定条件を確認してモデル化する。対応済みと仮定しない。

## 4. 検証エンジンとデータ

- 日米市場、為替、決算、分割、配当のイベントをUTC時刻順に扱う。注文時に未知の同日米国始値や為替終値を使わない。
- 執行時点のレートと期末評価レートを分離。USD現金を含む通貨別台帳と、株式分割・配当・上場廃止の台帳処理を共通化する。
- 当時の構成銘柄・上場廃止・公表時点付き財務情報について、取得範囲・利用権・欠落を確認する。現在のYahoo株価だけで完全な履歴が揃うと仮定しない。
- 監視候補と注文理由を再現可能に保存する。将来の他市場価格・為替・財務情報を改変しても、それ以前の候補・判断・約定が変わらないことをテストする。

## 5. 将来10年へ向けた評価

すでに見た2021〜2026年の結果は開発・診断用であり、完全な未使用データとは呼ばない。評価用期間と採否基準を先に固定し、過去区間で条件を決めて、その次の区間だけで評価する手順を繰り返す。候補集合も各時点で再構築する。

可能な範囲で15〜20年以上を用い、複数開始月、下落・横ばい・上昇相場、銘柄除外、費用増加で確認する。履歴が短い企業は上場前の価格を補完せず、当時の適格集合に沿って参加させる。NVIDIA等の上位寄与銘柄を除いた場合は、資金配分も含めて再実行する。

比較相手は円換算・配当・費用・投資可能性を揃えたS&P500、日経平均/TOPIX、指数＋現金。収益だけでなく最大下落、変動率、損失回復期間、資金稼働率、利益集中度を評価する。新しいルールの採用条件は、未使用期間でも同程度のリスクの基準運用に対して改善が残ること。

10年100倍は資金目標であり、固定シードの未来シミュレーションや少数の勝ち銘柄で検証済みにはできない。候補拡張で見つける機会を増やし、損失管理・実行可能性・未使用期間の成績を同時に評価する。
