# KABU LAB

日本株・米国株の売買を、仮想資金で検証するスマホ対応アプリです。

**アプリ:** https://kabu-lab-0514.azurespoon512.chatgpt.site

アプリは本人のChatGPTアカウントで開く非公開Sitesです。スマホでも同じアカウントでサインインしてください。

実注文を出す機能や証券口座への接続はありません。初期画面の価格は固定シードで生成した合成サンプルで、実際の株価・運用実績ではありません。

## できること

- 自動売買の開始・停止と20日連続実行。前日終値から売買判断し、翌取引日の始値で自動約定。
- 日本語のレスポンシブ画面。スマホのブラウザで操作、ホーム画面への追加に対応するmanifest。
- 日本株100株・米国株1株単位の仮想売買。注文翌日の始値で約定、取引履歴CSV。
- 日別の円換算、売買手数料・スリッページ・為替コスト。日本と米国の異なる休場日をCSVで表現可能。
- 中リスク／高リスクの保有比率上限、終値ベースの損切り、資産全体の下落による買付停止。
- MA20/60と20日モメンタムの戦略バックテスト。買い持ち参考値、CAGR、最大ドローダウン。
- 初期資金・積立・期待収益率・変動率を変更する10年間／2,000経路のモンテカルロ。100倍の目標額到達、元本割れ、50%以上の下落経験の割合。
- 株価CSVの検証・取込、仮想口座リセット。ブラウザのlocalStorageに保存。

## 使い方

1. アプリを開く。まず合成サンプルで操作を試せます。初期資金100万円、高リスク、レバレッジなし。
2. ダッシュボードか「仮想売買」の「自動売買を開始」で、約0.7秒ごとにデータ上の1取引日を進め、判断・注文・約定を自動実行します。「20日分を自動実行」も選べます。「停止」で再生を止めます。手動注文も利用できます。
3. 「戦略を検証」で日本／米国／両方を選びバックテスト。「10年の未来」で目標達成の難しさも確認します。
4. 実際の過去データは「データ・設定」からCSVで取り込みます。取込時は仮想口座をリセットします。

自動売買は**過去データの自動再生による仮想運用**です。画面を閉じる、非表示にする、設定等の別画面に移ると停止します。再読み込み後は自動再開しません。停止しても保有株・未約定注文は残ります。保存失敗・データ末尾で停止し、口座の下落上限到達時は新規買付を止め、売却処理を終えて停止します。楽天証券の実株を無人で売買する機能ではありません。詳細なアルゴリズムは [自動売買の設計](docs/algorithm.md) を参照してください。

データは端末内保存です。他端末への同期や、画面を閉じている間の自動運用はありません。ブラウザのデータ削除に備え、取引履歴をCSV保存してください。コードは公開、配信サイトは本人限定です。端末内の取引記録はGitHubやサイトのサーバーに送信されません。

## 目標とリスク

積立なしで10年間に100倍にするには、複利で **年率約58.49%** が必要です。中〜高リスクの運用でこの成長を実現できると想定していません。目標を達成するために利回りを自動で引き上げる実装はしていません。

| 設定 | 中リスク | 高リスク |
| --- | --- | --- |
| 1銘柄上限 | 20% | 30% |
| 株式比率上限 | 80% | 90% |
| 終値ベースの損切り目安 | 10% | 15% |
| 自動戦略の1回想定損失枠 | 1% | 2% |
| 資産最高値からの買付停止幅 | 25% | 40% |
| モンテカルロの説明用期待収益率 | 8% | 12% |
| モンテカルロの説明用変動率 | 20% | 35% |

これらは運用方針を試すための設定値で、リスクを保証する分類ではありません。損切りは翌始値で執行するため、ギャップで設定以上の損失が出ます。詳細は [検証モデル](docs/model.md) を参照してください。

## 開発

Node.js 22以上、Python 3を利用します。アプリ自体にパッケージ依存・ビルド工程はありません。

```sh
npm test
npm run check
npm run build # 配信物を dist/ に生成（ローカル起動だけなら不要）
npm start
# http://localhost:8000
```

ブラウザ検証（任意、別途PlaywrightとChromiumが必要）:

```sh
pip install playwright
CHROMIUM_PATH=/usr/bin/chromium python tests/browser_smoke.py
CHROMIUM_PATH=/usr/bin/chromium python tests/browser_auto.py
```

- `src/engine.js`: データ・注文・リスク・バックテスト・確率シミュレーション
- `src/app.js`: 日本語画面、チャート、CSV操作、端末内保存
- `tests/engine.test.js`: 約定・FX・コスト・先読み防止・損切り等のテスト
- `tests/browser_smoke.py`: スマホ画面の実操作と再読み込みの検証

コードはこのリポジトリの `main`、配信先は上記の非公開Sitesです。`.openai/hosting.json` に既存SiteのIDと静的配信ディレクトリを記録しています。Sitesのソースへの同期・公開はSitesの認証付きワークフローで行います（GitHubへのpushだけではSitesへ自動反映しません）。CIでエンジンテスト・構文チェック・配信物の生成を行います。

GitHub Pagesの有効化は、接続アプリのPages管理権限がなくHTTP 403になったため未実施です。将来Pagesを使う場合は、リポジトリ管理者がSettings → Pagesでmainのルート配信を設定できます。`.nojekyll` はそのために同梱しています。

## 楽天証券への将来の接続

現時点では**未接続**です。口座情報・APIキー・パスワードを入力しないでください。

2026-10-23に確認した[楽天証券のRSS注文仕様](https://marketspeed.jp/ms2_rss/onlinehelp/ohm_002/ohm_002_06.html)には国内株式・先物OPの注文関数があり、米国株の注文関数は記載されていません。[公式の機能紹介](https://marketspeed.jp/ms2_rss/function/)ではExcel経由の利用が説明されています。スマホの画面だけでRSS実発注が動くものではありません。

次段階では、許諾された市場データ取得、認証付きサーバー保存、日次ペーパー運用と監視を先に追加し、その後に公式接続方式・対象商品・実行環境・注文照合・緊急停止を確認して実注文アダプターを設計します。米国株の実発注手段は別途検討が必要です。
